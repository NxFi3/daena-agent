# Upgrade from 0.3.0 to 0.4.0

Save `daena_agent-0.4.0.tar.gz` in Downloads and run in your existing Python environment:

```bash
cd ~/Desktop
tar -xzf ~/Downloads/daena_agent-0.4.0.tar.gz
cd daena_agent-0.4.0
python -m pip install -e '.[ollama,web]'
python -m cli --version
python -m cli --config config.json --cwd /home/itsnxfi3/Desktop/test
```

The supplied config now selects `qwen3.6:35b-a3b-q4_K_M`. Ollama must already be
running with that model available. Both the root and packaged default config
contain the same settings. Do not copy the whole old config over them; copy
specific credentials, skill directories or preferences as needed.

Run from the new directory: launching `python -m cli` from an old source folder
loads that source even after another version was installed. Project files are
not removed or reset by installation. Start a fresh conversation and ask Daena
to inspect and continue existing work.

## What changed

- Explicit `task_finish` separates progress narration from terminal responses.
  The model reports `completed`, `blocked`, or `needs_input` and any checks it
  actually performed. There is no task-specific or language-specific classifier.
- Workspace plans and recent complete tool exchanges survive follow-up turns.
  `plan.read` inspects the current plan; `plan.replace` explicitly replaces it
  while preserving its previous contents in `.daena/plan-history`.
- `make_directory` accepts a list of literal paths and creates parent directories.
  All paths are authorized before execution. No brace expansion is guessed.
- Ollama's read timeout is now `null` in the default config. Long local inference
  remains interruptible and displays waiting telemetry. Optional read-idle and
  overall deadlines are separate from connection timeouts. Error messages name
  the request stage, model and elapsed time. Partial streams and output-length
  truncation do not execute tool calls.

A directory named `{css,js,...}` left by an earlier literal-argv command is not
removed automatically. Inspect existing files before cleaning it up.

The transport tests use the real Ollama SDK with a local HTTP fixture. They
exercise delays, cancellation, deadlines, complete/incomplete responses and tool
exchanges without loading a model. These checks do not establish live Qwen
reasoning quality, generation speed, GPU availability or production readiness
of a project generated by the model.
